## Shipped

- `packages/tools`: an MCP server on the official TypeScript SDK v2 (`@modelcontextprotocol/server`), streamable HTTP, bearer token from `MCP_BEARER_TOKEN`. Mounted at `/api/mcp` (`apps/web/src/app/api/mcp/route.ts`). Serves the 2026-07-28 protocol and, statelessly, 2025-era clients.
- Five tools:
  - `query(sql)`: one read-only query, at most 500 rows, 10 s timeout.
  - `trace_money(entity_id, direction, max_depth ≤ 5, min_amount)`: a recursive walk that returns paths with edge ids per hop.
  - `get_filing(filing_id)`: form, dates, PDF URL, and each line's schedule and line number.
  - `vote_base_rate(bill_id, motion)`: every member's vote on each matching roll call.
  - `cite(sentence, edge_ids)`: checks that the ids exist, inserts a `claim` row and returns its id.
- Five views (`v_money`, `v_lobby`, `v_votes`, `v_entities`, `v_interests`) and two roles (`agent_ro`, `claim_writer`) in `packages/db/src/schema.ts`. Migration `0001_agent_views` was generated by drizzle-kit, not hand-edited.
- `packages/tools/sql/grants.sql`: the human step drizzle-kit cannot express. It grants `agent_ro` SELECT on the views only, sets its 10 s timeout and read-only default, and grants `claim_writer` INSERT on `claim` only.
- Filing free text (names, motions, bill titles, entity attrs) comes back as `{"untrusted_text": ...}`. In `query` results, every text value is wrapped unless it comes straight from a known code, key or URL column.
- `cite` refuses the banned phrases from AGENTS.md rule 10.

## Broke or learned

- postgres.js `sql.unsafe(text)` with no parameters uses the simple protocol, which runs several statements. A test injected `select 1) as q; delete from money_edge; select (1`, and only the read-only transaction stopped the DELETE. `query` now forces `{ simple: false }`, so Postgres refuses more than one statement, and the test expects that error.
- Bun's `expect(...).rejects` hangs on postgres.js queries, which only run when awaited. The tests await them inside an async helper.
- Postgres view-column oids differ per database, so the cache that decides which columns to wrap is kept per connection pool. If the views change while the server runs, the cache matches nothing and every text column is wrapped, which is the safe direction.
- `next.config.ts` has `cacheComponents` on, which rejects `export const dynamic`. The route doesn't need it.
- One contribution shows up on as many as five schedules: F497P1, F497P2, the recipient's Schedule A, and the giver's Schedule E and D. `trace_money` lists every edge on a hop and ranks counterparties by their largest single edge, not by a sum, so nothing is double counted.
- drizzle-kit 0.31 creates roles and views but has no GRANT, LOGIN or `ALTER ROLE … SET`, so those stay a human step. `drizzle.config.ts` now manages only the two new roles, which leaves Neon's own roles alone.
- Nothing was applied to Neon. The tests never read Neon either; they ran on a local cluster only.
